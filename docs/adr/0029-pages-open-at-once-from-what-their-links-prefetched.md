# Pages open at once, from what their links prefetched

Next.js 16.3 made a click show the next page at once, before the server answers, when Cache Components and Partial Prefetching are on. Each `<Link>` on screen prefetches its page's App Shell: what the page shows whatever its address, without data that has to be fetched for the request. A click renders it straight away and the rest streams in. Both flags are on in the app and on the marketing site (`next.config.mjs`). In exchange, whatever reads the request, uncached data or the time sits under a Suspense boundary, the build checks that every page has a shell, and `next dev` reports, in its overlay and terminal, any navigation that would wait for the server.

Most of the app was already shaped for it: its pages are client components that load their data from Convex. What stood in the way was on the server. The root layout reads the sign-in from the request's cookies, and Convex Auth notes the time it read them, so it waits for the request (`connection()`) under Suspense. The build then prepares an empty shell for each language: a page loaded directly still waits for the request, as it always did, and moving between pages never renders the root layout again. The app's frame (the dashboard layout) asks Convex for the user and their firms in a component under Suspense, with the token from `convexToken()` (`src/lib/convex-server.ts`), which also waits for the request: Convex's HTTP client gives each read a random id, and a read answers for the moment it runs, so neither belongs in a prefetch. The frame stays put between its pages, so this shows only when someone comes into it from outside, as an empty frame that fills when Convex answers. The staff check of the admin pages runs the same way, under `"use cache: private"`, so the browser keeps its answer for five minutes and a link's prefetch already holds the admin pages. Every admin function still checks in Convex.

An address can't be part of a shell all its links share, so a page's server component no longer awaits `params`. Its client component reads the address with `useRouteParam` (`src/components/use-route-param.ts`), or with `useSearchParams` for the query, and loads its data as before. The pages that only sent people elsewhere, `/` to the Devize and `/admin` to its producers, became redirects in `next.config.mjs`, which answer before anything renders and which prefetches follow. An Ofertă link's title still reads its token and Convex for each request, so its page tells Next.js it renders per request with an empty part that waits for one.

## Consequences

- Against a production build, with every navigation request held back, the sidebar's pages and Admin opened with no request to the server at all, and a Deviz's page opened on its own loading state while Convex answered.
- Next.js keeps the last pages someone left mounted but hidden (React's Activity), so Back and Forward show them as they were. A hidden page's effects stop, so its Convex queries pause until it shows again. `useParams()` and `usePathname()` in a hidden page follow the address now shown, which is why `useRouteParam` keeps the value the page opened with.
- A link to a kept page also shows it as it was left. The new Deviz dialog closes before it opens the new Deviz. The new norm's form starts empty when a link opens it, keyed by the router's `bfcacheId`, and gives its place in the history to the saved norm. The catalog's list, the public one or the firm's own, is read from the address.
- Only links prefetch. `router.push` to an address no link prefetched waits for the server, so a menu item that opens a page is a link (`DropdownMenuItem asChild` around a `Link`), as the Deviz's Coș and Materiale and the firm switcher's invitations now are. Opening the Deviz just created still waits, since no link could know its address.
- Signing out deletes a cookie in a server action, which makes Next.js drop the kept pages and the prefetches, staff check included, and signing in always loads the page anew.
- A redirect or a not-found page decided under Suspense streams in: an account that hasn't finished onboarding, or someone outside Devize opening Admin, gets status 200 with the redirect or the not-found page, where it used to get 307 or 404.
- New server code that reads the request, the time or Convex goes in an async component under Suspense. `export const dynamic`, `revalidate` and `fetchCache` don't work under Cache Components. Nothing in CI checks navigations yet: `next dev` reports them and the build checks only the shells. An `instant()` test from `@next/playwright` would need a Convex backend in CI.
